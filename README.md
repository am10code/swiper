# Swiper — расширение для задач и фокуса

Расширение для Chrome/Chromium с управлением задачами, рабочими очередями и карточкой фокуса.

## Возможности

- Создание, редактирование и завершение задач, быстрые действия и контекстное меню.
- Категории и срочность (обычный/высокий), дедлайны с подсветкой.
- Отдельная приоритизация порядка задач через попарные сравнения (экран «Что важнее»): числовой ранг не показывается в UI, но используется для сортировки задач во всех основных секциях.
- Разделы задач: просроченные, на сегодня, позже (по умолчанию свёрнут), «Без даты» (по умолчанию свёрнут); при создании задачи с пустым полем дедлайна подставляется «Сегодня». Режим отображения «все» или «только сегодня».
- Вверху страницы задач есть рабочая панель с входами в основные действия: `Делать` (ФЛОУ), `Разобрать` (Движение), `Короткие`, `Жду` и `Что важнее` при наличии неприоритизированных задач.
- Секция «Просрочено»: карточки нейтральные (без красной полосы), красный только в заголовке секции и счётчике; текст просрочки с градацией (1–3 дня — жёлтый, дольше — красный). В заголовке секции — кнопка триажа «Перенести всё на сегодня» (с подтверждением, видна при 2+ просроченных); на карточке просроченной задачи по hover — быстрая кнопка «Сегодня» (перенос с проверкой перегруза дня).
- В списке задач есть компактная кнопка «Что важнее» для неприоритизированных задач: если есть хотя бы одна активная задача без ранга, кнопка видна; после завершения последнего сравнения скрывается. На кнопке — бейдж-счётчик количества задач без приоритета (9+ при переполнении), количество дублируется в tooltip. Кнопка ФЛОУ — статичный приглушённый градиент без анимаций и бликов.
- Режим ввода новых задач в настройках: «Поле внизу» (по умолчанию) или «FAB»; при FAB нижнее поле открывается по клику на кнопку `+` справа внизу.
- Полная карточка задачи: следующие шаги (drag & drop), лог, фокус‑таймер, поле ссылки с валидацией `http/https`; в меню «Больше опций» можно **сбросить вес задачи** (обнулить скрытый ранг приоритизации `priorityRank` — задача снова попадает в пул неприоритизированных, срочность high/medium не меняется).
- Редактирование задачи выполняется через полную карточку; в списках задач кнопка карандаша скрыта.
- В блоке «Следующий шаг»: клик по строке шага переключает выполненность, корзина удаляет шаг.
- В карточках списков задач состояния по умолчанию не маркируются: бейдж статуса показывается только для `Черновик` (`draft`, нейтральный стиль); для `ready` бейдж не выводится. Бейдж «без оценки» не показывается — бейдж оценки виден только при заданной оценке. Строка следующего шага рендерится только когда шаг есть (плейсхолдер «Добавьте следующий шаг...» в списках убран).
- В полной карточке для `draft` основная кнопка меняется на «Пометить как готово к работе»: перед переводом в `ready` запускается чек готовности, а при провале показывается конкретный список недостающих пунктов (включая требование декомпозиции для сложных задач).
- В рабочих активных списках и в режиме ФЛОУ исполнения участвуют только задачи со статусом `ready`; `draft` не попадают в production-ранжирование до прохождения чека готовности.
- У повторяющихся задач рядом с названием показывается серый символ повтора `↻` (индикатор, без действия).
- Режим «регулярное участие»: «Выполнено на сегодня» с переносом дедлайна на период регулярности; тип регулярности задаётся через `recurrenceExecutionMode` (`routine` — задача сама является действием, `needs_next_action` — нужен следующий шаг).
- В редактировании карточки: быстрые дедлайны «Сегодня», «Завтра», «На следующей неделе» (следующий понедельник); поля периода и типа регулярности видны только при включенном «Регулярное участие».
- В редактировании полной карточки можно управлять оценкой времени: `estimateMode` (`fixed|range|epic|none`), пресеты минут (5/15/30/45/60/90/120/180/240/360) и диапазон `min/max` для `range`; изменения сохраняются сразу.
- В полной карточке задач с оценкой показывается блок план/факт: план (по оценке), факт (по фокус-времени), отклонение в процентах и подсказка при сильном перерасходе/недорасходе; для задач без оценки блок скрыт.
- При завершении/остановке помодоро-сессии в карточке задачи синхронно обновляются обе метрики времени: `totalTime` и `actualFocusSeconds` (включая fallback для legacy-данных).
- **Автодедлайн «Сегодня» в полной карточке** (только незавершённые задачи): перенос на сегодняшнюю локальную дату выполняется **только если текущий дедлайн просрочен** (строго раньше сегодня). При дедлайне «сегодня», в будущем или без даты дедлайн из‑за активности в карточке не меняется. Триггеры те же: следующие шаги (добавление, отметка, удаление, порядок), лог (включая «Выполнен шаг…»), **Старт** фокус‑помодоро, смена названия; в форме «Редактировать» — при изменении приоритета, ссылки или регулярности дата из поля перезаписывается на «сегодня» **только для просроченной** задачи; если меняли **только** дедлайн — сохраняется выбранная дата. Явные действия вроде «Перенести на следующую неделю» по-прежнему задают дедлайн вручную.
- Кнопка «Перейти к следующей задаче» в полной карточке на странице задач проходит очередь: сначала просроченные (по приоритету), затем сегодня (по приоритету), затем позже (по дедлайну; при равном дедлайне — по приоритету), затем без дедлайна.
- Попап подтверждения удаления задачи в полной карточке (`#taskDeleteModal`) всегда отображается поверх карточки, чтобы кнопку «Удалить» было можно нажать и не приходилось закрывать режим.
- Режим ФЛОУ: кнопка «ФЛОУ» в хедере (`main.html`) переключает на полноэкранный экран с одной задачей в виде полной карточки; порядок задач — объединенный список «просрочено + сегодня» по приоритету, затем задачи с дедлайном завтра и позже по дедлайну (при равном дедлайне — по приоритету), затем задачи без дедлайна. При входе в ФЛОУ сохраняется **снимок** этого порядка (id задач): внутри одного прохода «Перейти к следующей задаче», «Выполнено на сегодня» и «Отметить выполненной» ведут к следующей задаче **по снимку** (смена дедлайна в карточке не перескакивает очередь по свежей сортировке). После задачи с **последним** id в снимке выполняется **переснимок** по актуальным данным и открывается первая задача нового порядка — как при повторном входе в ФЛОУ, без закрытия карточки; дальше снова обход по новому снимку. Повторный клик по «ФЛОУ», когда режим уже открыт, не перезапускает вход. Выход только через бургер-меню (выбор любого раздела сбрасывает снимок и закрывает карточку). Подтвержденное удаление задачи в полной карточке в режиме ФЛОУ также использует обход по снимку: после удаления открывается следующая задача по снимку, а с последнего id выполняется переснимок; если задач больше нет, карточка закрывается и ФЛОУ завершается.
- В ФЛОУ доступен переключатель окна времени (`5/15/30/60/120` минут): выбранное значение сохраняется в `settings.activeFlowTimeWindowMin`, сразу пересчитывает очередь и влияет на time-aware ранжирование внутри каждого дедлайн-бакета через `fitScore`; для длинных задач добавляется `epicPenalty` (штраф при коротком окне, буст в deep-work окне `60+`). Если под выбранное короткое окно нет задач, ФЛОУ показывает явное пустое состояние вроде «Нет задач под 15 минут», а не открывает длинную карточку.
- Рутинные регулярные задачи без следующего шага считаются исполнимыми в ФЛОУ как самостоятельное действие с дефолтной оценкой 30 минут; регулярные задачи типа `needs_next_action` без шага поднимаются в раздел «Движение».
- В списках задач и в карточке задачи в режиме ФЛОУ показываются только полезные time-бейджи: ближайший шаг (`5м`, `30м`, тип действия) и оценка (`~15м`, `~2ч`); совместимость с текущим окном ФЛОУ учитывается в подборе, но не выводится отдельным бейджем.
- При создании задачи через FAB на странице задач форма закрывается, список обновляется и сразу открывается полная карточка новой задачи.
- В ФЛОУ “боевой” skip (`flowSkipCount`) учитывается только при явном `Следующая задача` без meaningful-progress в текущем открытии карточки; изменения лога, декомпозиции и значимых полей редактирования отменяют такой skip, а для `draft` skip не считается боевым.
- В Settings добавлено поле `Дневной capacity (мин)` (`settings.dailyCapacityMin`, диапазон `60-960`, default `240`): значение нормализуется при сохранении и используется в проверке перегруза дня для дедлайна «Сегодня».
- При попытке поставить дедлайн «Сегодня» в создании/редактировании и в карточке задачи выполняется `warn + override`: показывается риск перегруза (план vs capacity), предлагается ближайшая подходящая дата и дается выбор — оставить «Сегодня» или перенести.
- Раздел `Триаж` готовит сырые карточки к работе: черновики, задачи без следующего шага, без оценки или слишком крупные. Разбор идёт по одной карточке за раз с прогрессом и навигацией.
- Раздел `Движение` собирает задачи, которым нужен следующий управленческий шаг из-за давления или застревания: просроченные ожидания, дедлайновые неготовые карточки, повторно пролистаные и залежавшиеся. Разбор идёт по одной карточке за раз; обычные сырые карточки без давления остаются в `Триаже`, готовые к исполнению остаются в списке задач и ФЛОУ.
- Раздел `Cookbooks` в меню содержит практические сценарии использования: старт дня, малые слоты, deep work, мутные задачи, ожидание, залежавшиеся задачи, идеи/бэклог, конец дня и регулярные активности.
- Помодоро с историей сессий, итоговым временем и фоновым звуком (код использует пути `assets/audio/pomodoro-ambience.mp3` и `assets/audio/bell.wav`).
- В настройках помодоро используется структурированная форма с подсказками по каждому полю, а после сохранения показывается короткий статус; некорректные числовые значения автоматически приводятся к допустимому диапазону.
- Импорт/экспорт задач в `.swiper`/`.json` с обратной совместимостью (обязателен только `text`, лишние поля не ломают импорт); поле статуса `status` (`draft|ready`) принимается при импорте, при отсутствии/некорректном значении нормализуется в `ready`; `recurrenceExecutionMode` нормализуется в `routine|needs_next_action`; time-поля (`timeEstimateMin`, `timeEstimateUpdatedAt`, `actualFocusSeconds`, `estimateMode`, `timeEstimateMinRange`) импортируются миграционно-безопасно, для `estimateMode="range"` обязателен валидный диапазон `timeEstimateMinRange`, а `actualFocusSeconds` для legacy-данных синхронизируется с `totalTime`.
- Уведомления по дедлайнам и по завершению помодоро.
- Глобальная настройка `Логировать выполнение шагов`: при включении в лог задачи добавляется запись `Выполнен шаг ...` с временем закрытия шага; состояние чекбокса сохраняется сразу при переключении.
- Настройка режима добавления задач сохраняется сразу при переключении radio-кнопки.
- Выполненные задачи группируются по датам завершения («Сегодня», «Вчера», дата).

## Установка

1. Откройте Chrome и перейдите в `chrome://extensions/`.
2. Включите «Режим разработчика» (Developer mode).
3. Нажмите «Загрузить распакованное расширение» (Load unpacked).
4. Выберите папку с расширением.

## Точки входа

- По клику на иконку расширения service worker открывает `main.html` в новой вкладке (`chrome.action.onClicked` в `background/background.js`).
- `manifest.json` не содержит `action.default_popup`.
- `main.html` — production entrypoint основного интерфейса.
- `popup/popup.html` — legacy-страница (не production entrypoint и не action popup).

## Архитектура

- `popup/storage.js` — работа с данными в `chrome.storage.local`; модель задачи включает статус готовности `status` (`draft|ready`) и тип регулярности `recurrenceExecutionMode`; **новые задачи создаются со статусом `draft`**, существующие при миграции получают `ready`; поле skip-метрики `flowSkipCount`, настройки ФЛОУ/планирования (`settings.activeFlowTimeWindowMin`, `settings.dailyCapacityMin`) и time-поля (`timeEstimateMin`, `timeEstimateUpdatedAt`, `actualFocusSeconds`, `estimateMode`, `timeEstimateMinRange`) с fallback-миграцией для старых задач.
- `popup/popup.js` — логика разделов и списков задач + page-specific bootstrap для `main.html`/`popup/popup.html`; раздел «Движение», снимок очереди ФЛОУ (`flowSessionOrderedIds`, пересъёмка при новом цикле), переключатель окна времени ФЛОУ, проверка capacity для дедлайна «Сегодня» и экспорт `getCurrentSectionName`, `getFlowSessionOrderedIds`, `refreshFlowSessionSnapshot`, `getActiveFlowTimeWindowMin`, `validateDeadlineCapacity`.
- `popup/task-card.js` — полная карточка задачи и помодоро (идемпотентная инициализация через `initTaskCardPage`); навигация «следующая» в ФЛОУ по снимку сессии (`resolveNextFlowTaskId`) и time-aware ранжирование очереди (`fitScore + epicPenalty`) с учетом активного окна времени.
- `popup/modules/dialog-service.js` — модальные диалоги (showAlert/showConfirm) вместо alert/confirm.
- `popup/modules/import-export.js` — импорт/экспорт задач.
- `popup/modules/prioritization.js` — движок попарной приоритизации с инкрементальной вставкой (минимальное количество сравнений для новых задач).
- `background/background.js` — сервис‑воркер уведомлений и алармов (в т.ч. fallback-иконка уведомлений через data URL); при изменении задач напоминания по дедлайнам синхронизируются инкрементально с debounce 400 ms.


## Текущее состояние ассетов

- Для полной работы расширения нужны: **иконки** `assets/icons/icon16.png`, `icon48.png`, `icon128.png` (манифест, уведомления) и при необходимости **аудио** `assets/audio/bell.wav`, `assets/audio/pomodoro-ambience.mp3` (помодоро и уведомления). В репозитории по умолчанию только SVG в `assets/icons/` и инструкции в `assets/icons/README.txt` и `assets/audio/README.txt`.
- PNG можно получить конвертацией из SVG (см. `assets/icons/README.txt`). Ожидаемые аудио-файлы перечислены в `assets/audio/README.txt`.

## Отладочные логи

- В коде используется общий логгер `shared/logger.js`; уровень `debug` по умолчанию не выводится. Чтобы включить отладочный вывод: в консоли страницы расширения выполнить `localStorage.setItem('swiper_debug', '1')` или задать `window.__SWIPER_DEBUG__ = true` до загрузки скриптов.
- Для быстрой проверки UI во встроенном браузере на данных из `mock.swiper` есть сценарий [docs/ui-browser-check.md](docs/ui-browser-check.md) и локальный сервер `tools/ui-audit-server.mjs`.
